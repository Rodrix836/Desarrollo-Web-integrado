1. PREPARAR LA COPIA

Conserva tus cambios antes de cambiar de rama. Desde tu repositorio:
  git status --short --branch
  git fetch origin
  git switch mejoras-integrales
  git pull --ff-only origin mejoras-integrales

Si todavía no tienes una copia:
  git clone --branch mejoras-integrales https://github.com/Rodrix836/Desarrollo-Web-integrado.git
  cd Desarrollo-Web-integrado

Requisitos: Java 21, Maven, Node.js compatible con Angular 20 y Chrome.
Comprueba java -version, mvn.cmd -version, node --version y npm.cmd --version.
Si Maven usa Java 17, configura tu terminal con la ruta de tu JDK 21:
  $env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\jdk-21.0.3.9-hotspot'
  $env:Path = "$env:JAVA_HOME\bin;$env:Path"

2. INICIAR EL SISTEMA

Abre cuatro terminales desde la raíz del repositorio.
Terminal 1:
  .\scripts\iniciar-api.ps1 -Servicio auth
Terminal 2:
  .\scripts\iniciar-api.ps1 -Servicio residuos
Terminal 3:
  .\scripts\iniciar-api.ps1 -Servicio consultas
Terminal 4:
  cd frontend
  npm.cmd ci
  npm.cmd start

Espera el arranque y abre http://localhost:4200. Auth usa 8081, Residuos
8082 y Consultas 8083. La aplicación anterior en 8080 es independiente.
Detén los cuatro procesos con Ctrl+C al terminar.

El script genera una clave aleatoria compartida en .local/jwt-secret.txt.
Las bases H2 están en auth-api/data y residuos-api/data. No compartas ni
versiones esos archivos. Conserva las bases para recuperar tus datos.

3. CUENTAS Y PERMISOS

ADMIN: admin / admin123
  Registra, edita y elimina materiales; ve todo el inventario, responde
  solicitudes de intercambio y administra cuentas.
USER: user / user123
  Ve el catálogo disponible, envía solicitudes y cancela las propias
  pendientes. Las cuentas nuevas reciben este rol.

Empresa es un texto del material que identifica quién lo ofrece.
ReCiclo no incluye compras ni pagos.

4. RECORRIDO DE DEMOSTRACIÓN

  1. Entra como admin. Inicio presenta registros, disponibles, kilos y
     gráficos por tipo, principales empresas y mes. Solicitudes pendientes
     conduce a las propuestas recibidas.
  2. Abre Residuos > Registrar residuo. Indica tipo, cantidad positiva en
     kg y descripción. Sin Habilitar intercambio queda sin publicar.
  3. Para publicarlo marca Habilitar intercambio, completa empresa,
     preferencia y fecha. Hoy lo publica; una fecha futura genera un aviso.
  4. Abre el detalle y revisa la auditoría. Edita y guarda la cantidad.
  5. Residuos permite filtrar y recorrer diez registros por página. Al
     cambiar filtros vuelve a la primera página. Consultas combina filtros.
  6. Cierra sesión y entra como user. Abre el material disponible y usa
     Solicitar intercambio. Material ofrecido, cantidad y mensaje son
     opcionales. El mensaje admite hasta 500 caracteres.
  7. En Mis solicitudes puedes cancelar propuestas pendientes.
  8. Vuelve como admin y abre Solicitudes recibidas. Filtra por estado,
     escribe una respuesta opcional (hasta 300 caracteres) y acepta o
     rechaza. Aceptar retira el material y rechaza otras pendientes.
  9. Vuelve como user: Mis solicitudes muestra Aceptada y la respuesta,
     aunque el material ya no figure en el catálogo.
  10. Como admin, Usuarios permite cambiar nombre, rol, activar/desactivar
      y eliminar con confirmación. Los controles propios están deshabilitados.
  11. Mi perfil permite cambiar el nombre y la contraseña. Confirma la
      nueva contraseña, de al menos seis caracteres.
  12. En celular, abre ☰ para navegar, ver la cuenta o cerrar sesión.
      Navegar y pulsar Esc cierran el menú. Las tablas se muestran como
      tarjetas con etiquetas; los formularios ocupan todo el ancho.

5. API Y SWAGGER

Swagger solo está activo con el perfil dev, habilitado por los scripts:
  http://localhost:8081/swagger-ui.html
  http://localhost:8082/swagger-ui.html
  http://localhost:8083/swagger-ui.html

Importa docs/ReCiclo.postman_collection.json en Postman. Ejecuta Login
ADMIN y Login USER; sus pruebas guardan tokenAdmin y tokenUser separados.
Usa las variables residuoId, solicitudId y usuarioId para las operaciones.
El registro recibe username, password y nombre.

Auth:
  POST /api/auth/login, /register y /refresh
  GET y PUT /api/auth/me
  PUT /api/auth/me/password (actual, nueva)
  GET /api/usuarios
  PUT /api/usuarios/{id}, /{id}/rol y /{id}/estado
  DELETE /api/usuarios/{id}
Residuos:
  GET y POST /api/residuos; GET, PUT y DELETE /api/residuos/{id}
  GET /api/residuos/avisos, /pagina y /estadisticas
  POST /api/solicitudes; GET /api/solicitudes/mias
  PUT /api/solicitudes/{id}/cancelar
  GET /api/solicitudes; PUT /api/solicitudes/{id}/decision
Consultas:
  GET /api/consultas/residuos y /api/consultas/empresas

Los tokens viajan con Authorization: Bearer. Angular los guarda en
sessionStorage y los renueva cinco minutos antes del vencimiento.

6. PRUEBAS

Desde la raíz, con Java 21:
  mvn.cmd -B -f auth-api/pom.xml verify
  mvn.cmd -B -f residuos-api/pom.xml verify
  mvn.cmd -B -f consultas-api/pom.xml verify
Desde frontend:
  npm.cmd ci
  npx.cmd ng build
Con las APIs y Angular activos:
  npx.cmd playwright test

Playwright ejecuta escritorio y Pixel 7 y comprueba las pantallas a 375,
768 y 1280 px. Usa datos locales de desarrollo.

7. RESOLVER PROBLEMAS

401: inicia sesión de nuevo; verifica que los servicios usen la misma clave.
403: revisa el rol; en login indica cuenta desactivada.
429 en login: demasiados intentos; espera antes de volver a probar.
409: propuesta duplicada o decisión sobre una propuesta finalizada.
404: material no disponible o solicitud que no pertenece a la cuenta.
Puerto ocupado: detén la instancia anterior antes de iniciar otra.
Error de conexión: espera que las tres APIs y Angular estén activos.
Tras cambiar un rol, cierra sesión y vuelve a entrar para renovar permisos.
